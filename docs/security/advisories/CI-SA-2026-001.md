Affected and fixed versions refer to CodeIndexer binary releases.

## Summary

The HTTP server did not validate the `Host` header of incoming requests. A web page whose domain name was re-pointed to the loopback address (DNS rebinding) could therefore be treated by the browser as same-origin with a CodeIndexer server running on the visitor’s machine.

## Impact

On an installation without a dashboard password, such a page could read data served by the dashboard and its API — memory cards, project paths, per-project configuration and code-search results — and call the state-changing dashboard API endpoints, none of which required credentials on such an installation. On installations with a dashboard password set, endpoints that require a session were not exposed: the session cookie is scoped to the host name the user signed in on, so the rebound page does not carry it. The dashboard password option exists since v0.6.0; earlier releases had no password option.

## Preconditions

- The CodeIndexer HTTP server is running and reachable from the user’s browser; the default loopback bind (`127.0.0.1`) is sufficient.
- No dashboard password is configured — the default, and the only possible state before v0.6.0.
- The user opens a web page controlled by an attacker who also controls DNS for that page’s domain.
- No credentials are required.

## Affected component

HTTP server of `codeindexer serve` — the router that serves the web dashboard, the dashboard API and the MCP HTTP endpoints.

Source modules: `src/mcp/mod.rs`, `src/mcp/host_guard.rs`, `src/config.rs`

## Remediation

**Upgrade to CodeIndexer v0.12.0 or later.** No alternative workaround is documented.

- First fixed version: v0.12.0
- Recommended upgrade: v0.12.0 or later, which includes the fixes for every advisory currently published in this collection.

v0.12.0 adds a Host allowlist as the outermost layer of the HTTP router. Loopback names and IP-address literals are always accepted, names listed in the `allowed_hosts` setting are accepted, and requests naming any other host are refused with HTTP 421 (Misdirected Request). If you reach the server through a custom host name, add that name to `allowed_hosts` after upgrading.
