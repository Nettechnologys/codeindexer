## Summary

API keys can be limited to a list of projects. The documentation and the configuration template presented this restriction as enforced, but the MCP tool handlers authenticated the key without consulting its project list.

## Impact

A holder of a key restricted to one project — or an AI agent using such a key — could search, run call-graph and audit queries over, and reindex, relocate or delete any project indexed on the server. v0.7.0 enforced the restriction for those tools; the memory and knowledge tools remained unrestricted until v0.12.0, so a restricted key could still read, edit and delete other projects’ memory cards, reports and solutions.

## Preconditions

- The server is configured with `[auth] api_keys` and at least one key restricted to specific projects (not a wildcard key).
- The attacker holds such a key, or controls an AI agent that uses one.
- Installations without project-restricted API keys are not affected.

## Affected component

MCP tool dispatch and the project-scoped MCP tools; API-key authentication (`[auth] api_keys`).

Source modules: `src/mcp/types.rs`, `src/mcp/mod.rs`, `src/mcp/tools/`

## Remediation

**Upgrade to CodeIndexer v0.12.0 or later.** No alternative workaround is documented.

- Fully remediated in: v0.12.0 — Code search, call-graph, audit and project-management tools enforce the restriction since v0.7.0; memory-card, solutions, reports, roadmap and card-chat tools since v0.12.0.
- Recommended upgrade: v0.12.0 or later, which includes the fixes for every advisory currently published in this collection.

v0.7.0 makes authentication return the key’s configuration, adds a project-access check and applies it in the project-scoped tools, including wildcard and reindex-all selectors. v0.12.0 applies the same restriction to the memory and knowledge tools.
