## Summary

The dashboard’s source-lines endpoint appended the requested file path to the project’s root directory without checking that the result stayed inside it, and returned the file’s contents. The same endpoint did not apply the per-key project restriction of API keys.

## Impact

A caller with access to the dashboard could read any file readable by the operating-system account running CodeIndexer, outside every indexed project. From v0.9.0, when API keys could be used to sign in to the dashboard, a key restricted to one project could also read the source of other indexed projects. The effect is limited to reading files.

## Preconditions

- A dashboard session. On an installation without a dashboard password every requester has one; on a team server, any holder of the dashboard password and, from v0.9.0, any holder of an API key — including a key restricted to a single project.
- On a default loopback installation, reading responses from an unrelated website depended on the DNS-rebinding issue described in [CI-SA-2026-001](CI-SA-2026-001.md).

## Affected component

Web dashboard API — the source-lines endpoint (`GET /api/source-lines`) that the dashboard uses to display file excerpts.

Source modules: `src/mcp/dashboard.rs`

## Remediation

**Upgrade to CodeIndexer v0.12.0 or later.** No alternative workaround is documented.

- First fixed version: v0.11.0
- Recommended upgrade: v0.12.0 or later, which includes the fixes for every advisory currently published in this collection.

v0.11.0 resolves the project before touching the file system, checks that the caller may access that project, canonicalises the project root and the requested path, and refuses any path that resolves outside the root. Error cases now return 400, 403 or 404 status codes instead of a successful response.
