Affected and fixed versions refer to CodeIndexer binary releases.

## Summary

When indexing a nested archive, the name of a TAR archive member was used unchanged as the write path inside the temporary extraction directory. A member name containing parent-directory components or an absolute path could place the extracted file outside that directory.

## Impact

A crafted archive in an indexed repository could make the server write attacker-controlled content to a path outside the extraction directory, with the permissions of the account running CodeIndexer. The target file name had to end in a recognised archive extension, which keeps the issue short of an arbitrary file overwrite. A related variant in RAR handling could read files outside the temporary directory on Unix hosts where `unrar` is installed.

## Preconditions

- The server indexes a repository, or an archive inside it, that contains a crafted TAR archive.
- Archive indexing is enabled — the default, with nested-archive recursion depth 1.
- No network access or credentials are required.

## Affected component

Archive indexing — extraction of nested archives during indexing.

Source modules: `src/indexer/archive.rs`, `src/indexer/indexing.rs`

## Remediation

**Upgrade to CodeIndexer v0.12.0 or later.** No alternative workaround is documented.

- First fixed version: v0.7.0
- Recommended upgrade: v0.12.0 or later, which includes the fixes for every advisory currently published in this collection.

v0.7.0 sanitises archive member names component by component, canonicalises extracted RAR paths and checks that they stay inside the extraction directory, and validates project names in the index and reindex entry points.
