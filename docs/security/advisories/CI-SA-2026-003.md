## Affected versions by component

| Component | Affected versions | Fixed in |
|---|---|---|
| Directory removal through the MCP project-delete tool | v0.2.0 – v0.11.0 | v0.12.0 |
| Directory removal through the HTTP projects API | v0.3.0 – v0.11.0 | v0.12.0 |
| Index-metadata repair triggered by read requests | v0.9.0 – v0.11.0 | v0.12.0 |

## Summary

Project names supplied in requests were used as directory names under the index root without validation. A name in the form of an absolute path, or one containing parent-directory components, could therefore refer to a directory outside the index root.

## Impact

Deleting a project by such a name removed the referenced directory recursively, with the permissions of the account running CodeIndexer; the server’s own internal knowledge store could be deleted the same way. From v0.9.0, a read request naming such a directory could also trigger the automatic repair of index metadata in it — restoring a backup copy over, or renaming, a `meta.json` file outside the index root.

## Preconditions

- Directory removal: a caller able to delete projects — from v0.2.0 an MCP client (including an AI agent following injected instructions); from v0.3.0 also a caller of the HTTP projects API, such as a local process or a page with same-origin access to the server (see [CI-SA-2026-001](CI-SA-2026-001.md)).
- Metadata repair: a read (GET) request that names the project; the review assessed this as reachable through a cross-site navigation.
- The default configuration is affected; no optional feature needs to be enabled.

## Affected component

Index store and project management — project deletion over MCP and the HTTP API, and the index-metadata (`meta.json`) loader used when a project is looked up.

Source modules: `src/indexer/store/meta.rs`, `src/indexer/store/mod.rs`, `src/indexer/project_admin.rs`, `src/mcp/api/projects.rs`

## Remediation

**Upgrade to CodeIndexer v0.12.0 or later.** No alternative workaround is documented.

- First fixed version: v0.12.0
- Recommended upgrade: v0.12.0 or later, which includes the fixes for every advisory currently published in this collection.

v0.12.0 validates every project name before any file-system use, refuses absolute and parent-relative names (including percent-encoded path segments), and treats deletion by path as a caller error.
